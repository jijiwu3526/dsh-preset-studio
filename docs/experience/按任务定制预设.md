# 按任务定制 DSH 预设：实践记录与结论

> [!WARNING]
> **本文描述的是 DSH 0.1.5 时代的机制，部分内容在 0.2 已过时。**
>
> **已过时**：第 1、2 节所依赖的「目录式 preset」——`@deepseek-ai/dsh-agent-presets`
> 扫描 `~/.dsh/.agent-presets/<id>/`、读取 `preset.yml` + `agent.cordis.yml`。
> 0.2 换成了 `@deepseek-ai/dsh-agent-preset-registry`，**不扫描目录、不接受 preset 路径、
> 没有任何接口接受 YAML 写回**，新机制是「在 bundle patch 里写 `preset-<id>` 行」。
> 详见 [`DSH-0.2-迁移笔记.md`](DSH-0.2-迁移笔记.md) 第 3 节。
>
> **依然有效**：本文的核心结论——**preset 是叠加层，裁剪不了宿主注入的工具**——
> 在 0.2 依然成立（实测：8 个插件行的 preset 实际拿到 52 个工具）。
> 因此**本文的 profile 层方法（`cordis.patch.yml` + `disabled: true`）在 0.2 仍然有效**，
> 变化的只是 preset 的**声明方式**，不是分层模型。
>
> 原文保留不动，供对照阅读。

本文记录一次完整实践：从「我想让智能体按任务需求配置一套工具组合」这个诉求出发，
到最终跑通 **preset 白名单 + profile 层开关 = 真正的最小工具集**。

所有数字都是本机实测，不是推断。复现命令全部给出。

---

## 1. 起点：预设裁剪为什么没用

最初的方案很自然：写一个 `agent.cordis.yml`，只列本次任务需要的插件。
结果实测**几乎完全无效**。

| 阶段 | 会话实际工具数 |
| --- | --- |
| `standard` preset | 117 |
| 自定义最小白名单 preset | **101** |

少掉的 16 个全在 `univer_*`，而**该去掉的 `subagent` / `workflow` / `agent-teams`
一个没少**——因为它们由宿主 profile 注入，preset 够不着。

官方文档给出了原因（`@deepseek-ai/dsh-agent-presets` README）：

> 从 preset 组装的会话会运行该 preset `agent.cordis.yml` 所列插件。
> **没有本包时，会话只能回退到宿主组装挂载的内容。**

**preset 是叠加层，不是替代层。**

> 注意：作者在 `presets/README.md` 里已经记录了同一条边界
> （「宿主 profile 注入的 `mcp__*` 裁剪不到——要真正限制工具面必须在宿主配置层处理」）。
> 本文补上的是**宿主配置层具体怎么做**。

---

## 2. 分层模型

```
preset  层  →  在宿主给定的工具之上做叠加与覆盖      ✅ 能做
profile 层  →  决定宿主提供哪些插件（工具集上限）    ✅ 决定性
```

本机 `web` profile 的 `package.json` 里 `dsh.profile.bundles` 有 27 个 bundle，
其中这些直接注入工具：

| bundle | 注入的工具数 |
| --- | --- |
| `@nanmicoder/dsh-agent-teams` | ~15 |
| `dsh-univer-office` | ~15 |
| `dsh-mnemon` | ~15 |
| `@yuxianglin/dsh-bridge-browser` | ~12 |
| `dsh-taskboard` | ~11 |
| `dsh-code-index` | ~7 |
| `dsh-logicprobe` | ~6 |

**能反向关掉它们的是 `cordis.patch.yml`**——profile 的 patch 层在所有 bundle 层
*之后* 应用，因此 `disabled: true` 胜出。

```
~/.dsh/profiles/web/cordis.patch.yml
```

### 最终效果

| 组合 | 工具数 |
| --- | --- |
| `standard` | 117 |
| preset 白名单（单独） | 101 |
| **preset 白名单 + 关掉 10 个 bundle** | **14** |

101 → 14，preset 里的白名单与结果**严丝合缝**。

## 3. 正确的工作流

```
用户描述任务
  ↓
① 判断需要哪些能力 → tools/profile-tool-switch.ps1 开关 bundle
② 写 preset（只列本次需要的行 + 必填 config）
③ dsh-session new 建会话并发任务书
  ↓
④ 用会话日志里的 request/header 核实真实工具集
```

第 ④ 步不能省。详见第 5 节。

### 用法

```powershell
# 看当前状态
.\tools\profile-tool-switch.ps1 -State

# 关掉一批（本次任务不需要的）
.\tools\profile-tool-switch.ps1 -Off univer,mnemon-bundle,dsh-taskboard

# 开回来
.\tools\profile-tool-switch.ps1 -On univer

# 核实：读合成后的真实配置，不要凭印象
.\tools\profile-tool-switch.ps1 -Verify
```

建会话（`--register-workspace` 不能省，见第 6 节）：

```powershell
dsh-session new --preset plan-executor `
  --workspace-path "C:\path\to\project" --register-workspace
```

## 4. 踩坑记录

### 4.1 行 id 不等于 bundle 名：`mnemon` vs `mnemon-bundle`

`dsh-mnemon` 注入的是一个 `cordis:group`，真实行 id 是 **`mnemon-bundle`**。

写 `- id: mnemon` → **静默无效**，不报错。

实测：一次关 10 个，只有 8 个生效。逐个 `-Verify` 才发现 mnemon 没中。
**如果当时没核实，会以为成功了。**

```yaml
# 错误 —— 什么都不会发生
- id: mnemon
  disabled: true

# 正确
- id: mnemon-bundle
  disabled: true
```

### 4.2 必填 config 缺失，报错只说第一行

preset 挂载失败时，错误信息**只指名第一个失败的行**：

```
agent-presets: preset "plan-executor" failed to mount: loader entries failed to apply
- failed to apply loader entry tool-fs-search: invalid config:
    - $.sampleOverCapGlobResults missing required value
```

修完这个又冒出下一个（`tool-todo` → `allowParallelInProgress`）。

**正确做法：不要逐个试错，直接从宿主抄准确值。**

```powershell
dsh --profile web --dump-config
# 找到对应 - id: <row>，把它的 config 整块复制过来
```

本仓库 `presets/*/agent.cordis.yml` 里已标注哪些行必填 config。

### 4.3 `tool-subagent-fork` 不是独立包

它是 `dsh-tool-subagent` 插件**内部**的一个 row id。
当独立包写会得到：

```
broken: row "tool-subagent-fork" names a plugin that cannot be resolved
```

而此时 `agentPresets/list` **仍显示 healthy** —— 只有真正建会话才会暴露。

### 4.4 `tool-subagent` 必填 config

```yaml
- id: tool-subagent
  name: '@deepseek-ai/dsh-tool-subagent'
  config:
    provider: spawn
    toolName: subagent
    backgroundMode: continuable
```

另外：宿主默认是 `disabled: true`，preset 里显式写出来等于**打开**它。

### 4.5 `persona` 的 `prefix` 必填

即使全部内容写在 `suffix` 里，`prefix` 也不能省，否则整个 preset 挂载失败。
（这条作者已在 `presets/README.md` 记录，本次再次踩中。）

### 4.6 装了 ≠ 启用了：`dsh-worktree`

`package.json` 的 `dependencies` 里有 `dsh-worktree`，但它**不在**
`dsh.profile.bundles` 里，且 `package.json` 中 `dsh` 字段为 `null`
（没有 bundle 声明）。结果：装了很久，一直是个死包。

激活方式（patch 层 insert）：

```yaml
- insert:
    - id: worktree
      name: 'dsh-worktree'
```

## 5. 唯一可信的验证方式

**不要相信配置，不要相信自己的记忆——去读会话日志里 DSH 发给模型的权威工具清单。**

```python
import zstandard, json, io
d = zstandard.ZstdDecompressor()
with open(LOG, 'rb') as fh:
    with d.stream_reader(fh) as r:
        for line in io.TextIOWrapper(r, encoding='utf-8', errors='replace'):
            e = json.loads(line)
            if e.get('type') == 'request/header':
                tools = ((e.get('data') or {}).get('header') or {}).get('tools') or []
                names = sorted({(x.get('name') if isinstance(x, dict) else x) for x in tools})
                print(len(names), names)
                break
```

会话日志在 `~/.dsh/sessions/<workspace-key>/<session-id>/session.v3.jsonl.zstd`，
是 **zstd 压缩**的（不是纯 `.jsonl`），需要 `zstandard` 包。

作者在 `docs/` 里记录过为什么必须用这个来源：**实测同一预设在「问模型你有哪些工具」
时得到过 13 / 2 / 0 三种不同自述结果。** 模型的自我报告不可信。

### `--dump-config` 也有局限

它能看到 `disabled: true` 是否合并进去，但**看不到 preset 层的最终效果**。
实测中它一度把 `bridge-browser` 报成未禁用，实际是检查窗口太小造成的误报。
**最终以会话日志为准。**

## 6. 工作区分组：`--register-workspace` 不能省

```powershell
# 错 —— 只设 cwd，侧栏显示在「未分组」
dsh-session new --preset X --workspace-path "C:\some\dir"

# 对 —— 额外注册具名工作区
dsh-session new --preset X --workspace-path "C:\some\dir" --register-workspace
```

返回值可自查：

```jsonc
// 错：只有 cwd，没有 workspaceId
{ "location": { "cwd": "C:\\..." } }

// 对
{ "location": { "workspaceId": "23a1d218-..." } }
```

## 7. 作用域限制（必须知情）

**profile 层的开关是全局的**，不是 per-session：

- 关掉的 bundle 对该 profile 下**所有新会话**都失效
- 已经跑着的会话**不会**被撤销工具（工具 schema 在创建时固定）
- 必须**新建会话**才看得到变化

所以这是「为这个任务准备一套环境」，不是「给这一个会话发一个自定义工具集」。

要真正的 per-session 隔离，只能用**独立 profile**（`--from-default-profile`），
代价是每个任务重启一次 DSH。

---

## 8. 已知不适用的场景

- **skill / MCP 注入不受 preset 或 bundle 开关影响**（作者记录：某次 FCCA 计划书会话因
  agent preset 锁定无法单独增减工具型插件，但 skill/MCP 注入不受限）
- **插件的命令行工具**（`dsh-session` / `dshstudio`）不经过 preset
- 关 bundle 会连带关掉该插件的**非工具功能**（如 taskboard 的面板、mnemon 的记忆库），
  不只是它的工具。关之前想清楚是否需要那些能力。

---

## 9. 结论

「按任务定制工具集」在 DSH 上是**可实现的**，但需要两层同时动手：

| 层 | 作用 | 工具 |
| --- | --- | --- |
| profile | 决定工具集**上限** | `tools/profile-tool-switch.ps1` |
| preset | 在上限内**精确挑选**并注入 persona 纪律 | `presets/*/agent.cordis.yml` |

只做 preset 得不到你要的结果；只做 profile 得不到精确控制。

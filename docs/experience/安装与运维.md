# 安装与运维

## 1. 前置：让本机 CLI 能自行取得认证

`dsh_session.py` / `dshstudio` 是进程外工具，需要 DSH Web 的带 token URL。
不装插件时唯一获取方式是人从终端手抄，token 会进入 shell 历史和聊天记录。

```powershell
dsh plugin --profile web add github:jijiwu3526/dsh-local-bridge
```

本仓库的 `plugin/` 就是这个插件的源码（合并前的独立仓库）。

### 若 git 拉不下来（本机常见）

本机实测：`git` 直连 `github.com:443` 会被 reset，但 `codeload.github.com` /
`raw.githubusercontent.com` 走 CDN 可通。

```powershell
# 改走 tarball
Invoke-WebRequest -Uri 'https://codeload.github.com/jijiwu3526/dsh-local-bridge/zip/refs/heads/main' `
  -OutFile "$env:TEMP\lb.zip" -UseBasicParsing
Expand-Archive "$env:TEMP\lb.zip" -DestinationPath "$env:TEMP\lb" -Force

# 放进 plugin-src 再本地链接
$dst = "$env:USERPROFILE\.dsh\plugin-src\dsh-local-bridge"
New-Item -ItemType Directory -Force -Path $dst | Out-Null
Copy-Item "$env:TEMP\lb\dsh-local-bridge-main\lib" $dst -Recurse -Force
Copy-Item "$env:TEMP\lb\dsh-local-bridge-main\cordis.patch.yml" $dst -Force
Copy-Item "$env:TEMP\lb\dsh-local-bridge-main\package.json" $dst -Force

dsh plugin --profile web remove dsh-local-bridge
dsh plugin --profile web add "link:C:/Users/Administrator/.dsh/plugin-src/dsh-local-bridge"
```

> **必须用绝对路径。** 本机实测相对路径 `link:../../plugin-src/...` 会被多解析一层，
> 写成 `C:/Users/plugin-src/...`（`C:\Users` + 相对路径），安装目录为空，
> DSH 警告「declares no dsh.bundle」——而 `package.json` 里的 `dsh.bundle.patch`
> 声明本身完全正确。**是路径问题，不是 manifest 问题。**

验证：

```powershell
dsh plugin --profile web list | Select-String dsh-local-bridge
dsh --profile web --dump-config | Select-String dsh-local-bridge   # 应有命中
```

装完**必须完整重启 DSH 进程**（不是刷新页面）。0.1.0 版本有 disposer 泄漏，
热重载会撞上 `duplicate exact route` 导致桥接彻底不通。

## 2. 安装 Python 工具

**PyPI 上没有 `dsh-conversation-studio`**（`pip install` 报
`No matching distribution found`，PyPI JSON API 返回 404）。
README 里那句 `pip install` 是作者的愿望，须从源码装：

```powershell
git clone <this-repo>
cd dsh-preset-studio
python -m pip install .
```

装出两个命令：`dshstudio`（预设画像/推荐）、`dsh-session`（会话 CRUD）。

### 桥接自检

```powershell
dsh-session presets
```

不带 `--url`、不设 `DSH_WEB_URL` 仍能工作 = 桥接链路通了。

若报「无法连接 DSH Web」，说明 `local-bridge.secret` 里的密钥已过期
（DSH 重启过），重读一次即可。

## 4. 本机环境备忘

- **DSH 版本**：`0.1.5-rc.2`（preset 插件要求 `>=0.1.5-rc.1`）
- **PowerShell 5.1**，不是 7.x。`Join-String` 等 PS7 语法不可用。
- **控制台编码**：中文输出会乱码，需 `$env:PYTHONIOENCODING='utf-8'`。
  这只影响显示，接口返回的字节是正确的。
- **写文件**：用 `[System.IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding($false)))`。
  `Set-Content` 在 PS 5.1 会把 UTF-8 重写成 ANSI，中文注释变乱码。
- **git 身份未配置**（`user.name` / `user.email` 均为空）。
- **git 走 HTTPS 连 github.com 会被 reset**，但 **SSH 通道正常**
  （`ssh -T git@github.com` 已认证）。本仓库的 push 走 SSH。
- **Python 3.12.10**，已装 `zstandard`（读会话日志需要）。

## 5. 仓库自带测试的 Windows 已知失败

`python -m unittest discover -s tests` → 67 项，2 项在 Windows 上失败。
**均为平台差异，非代码缺陷**：

| 测试 | 失败原因 |
| --- | --- |
| `test_file_is_private` | 断言 `0o600`；Windows 用 ACL，`st_mode` 返回 `0o666` |
| `test_remote_session_create_and_cookie_export` | `UnicodeDecodeError: 'gbk'`；测试用 `Path.read_text()` 未指定 encoding |

功能本身正常——桥接密钥文件的所有者实测为 `BUILTIN\Administrators`。

---

## 6. 卸载

```powershell
dsh plugin --profile web remove dsh-local-bridge
python -m pip uninstall dsh-conversation-studio
```

然后**完整重启 DSH**。密钥文件在进程退出时自动删除。

preset 目录直接删 `~/.dsh/.agent-presets/<id>/` 即可（DSH 无写入 API，删了就没了，
所以才需要在本仓库 `presets/` 里留档）。
